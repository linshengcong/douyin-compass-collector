# 分类采集管理

网页入口为 `#/collection-categories`。目录按平台保存，目标范围按任务保存，二级/三级黑名单由该平台任务共用。完整祖先 ID 路径定位节点，名称只用于展示。父范围动态包含新三级分类；排除规则优先，不支持在已排除子树内添加白名单。

## 数据与执行边界

服务端保存目录快照、导入草稿及已发布规则版本。目录上传不会修改规则。首次导入不是发布，必须在网页核对并保存。页面无需登录，与现有共享工作台保持一致；上传目录和导入草稿复用 `RANKING_SYNC_TOKEN` 鉴权。

新批次在执行锁、幂等及补录判断后读取远程已发布规则，随后获取平台完整目录，校验并生成三级清单。每个批次固定配置版本、目录摘要、最终分类路径，在 PostgreSQL 与 Manifest 保存，批次目录另存 `category-catalog.json`。多个选择范围按规则顺序执行，各范围内部保持平台顺序，兼容淘宝原主根优先和指定三级清单的执行顺序。

新批次配置读取失败或未发布时停止，不回退。目录上传失败不影响已读取且在当次目录通过校验的规则，最新目录保存在 `runtime/category-catalogs/<platform>/pending.json`，下一次新批次重试。正在运行的批次不跟随网页变化。继续补录使用原批次快照及分类清单，不读取新规则；补录回退全量时才重新读取。

## 上线和初始化顺序

1. 部署 mall-server；按既有发布流程先备份，再显式执行 `python -m selection_api migrate-db`，创建分类目录头部、目录快照及规则版本表。
2. 部署 mall-web，沿用现有 `VITE_SELECTION_API_URL`，确认分类采集管理页面能加载。
3. 本机沿用 `RANKING_API_URL` 与 `RANKING_SYNC_TOKEN`，不添加全局凭证。先保持 YAML 模式，按各平台实际入口导入。

```sh
.venv/bin/python -m compass_collector categories-init --platform compass --config config/tasks.yaml
.venv/bin/python -m compass_collector categories-init --platform taobao --config config/taobao.yaml
```

默认在当前平台 `runtime/raw` 下寻找最近有效的原始分类目录，也支持 `--catalog /绝对路径/category-tree.json.gz`。不会读取另一平台的目录或合并其他 YAML。找不到目录时使用 `--refresh`，只打开平台页面获取分类目录，不采集商品，不创建商品批次。

```sh
.venv/bin/python -m compass_collector categories-init --platform taobao --config config/taobao.yaml --refresh
```

仅更新目录而不初始化草稿时追加 `--directory-only`。独立刷新保存原始响应，之后可直接运行不带 `--refresh` 的导入命令。导入接口拒绝覆盖已有草稿或发布规则；首次请求结果不确定时先查看页面状态，不能重复覆盖。

4. 网页点击编辑，核对旧名称的完整命中清单。未匹配名称必须明确移除或在树中选择对应排除节点，再保存。旧一级名称排除会展开成当前直属二级节点；这一迁移采用精确节点规则，未来新增同名或新二级分类不会自动继承旧名称排除。
5. 规则发布后，将各入口实际 YAML 中的对应平台设置为：

```yaml
platforms:
  taobao:
    category_config_source: remote
```

这是已有平台配置下的新增字段，其余字段继续保留。抖音在 `platforms.compass` 下设置。默认仍为 `yaml`，迁移完成前不切换。切换后重启旧 GUI/Scheduler 一次以读取来源模式，之后类目修改由每个新批次自动读取，不需要再次重启。

回滚时显式改回 `yaml` 并重启入口；保留服务端版本及历史批次，不删除数据。页面保存不启动采集，目录只有采集器上传后更新，无后台实时联动。

## 验证

采集器定向检查：`pytest tests/test_remote_categories.py tests/test_category_blacklist.py tests/test_category_batch.py tests/test_continuation.py`。真实数据库用例要求显式 `TEST_DATABASE_URL` 指向 `_test` 结尾的专用库，各例创建隔离 schema。

服务端检查：在 mall-server 下运行 `PYTHONPATH=. .venv/bin/python scripts/check_collection_categories.py`，使用同样的专用测试库。脚本覆盖鉴权、迁移草稿、目录迟到、并发发布、失效规则及两平台隔离。两个 Python 规则模块保持逐字一致；同级三项目工作区会自动验证一致性。

上线验收应分别记录：本地定向测试、前端静态检查/构建、浏览器合成数据全流程、实际平台新批次、生产部署。合成目录和本地测试库不能作为生产采集证据。
